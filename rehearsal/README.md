# ชุดซ้อมวันแข่ง (Rehearsal set) — คืออะไร ใช้ทำอะไร ใช้ยังไง

## 1) คืออะไร

**ข้อสอบซ้อม 500 ภาพ ครบทั้ง 72 คลาส พร้อมเฉลย** หน้าตาเหมือนชุดทดสอบจริงของวันแข่ง (`ts_img_001.jpg … ts_img_500.jpg` ลำดับสลับ ไม่เรียงตามคลาส ภาพ `.jpg` ขนาดเดิมของข้อมูล) แต่ **เรารู้เฉลย** จึงเอาไปเช็กได้ว่าสคริปต์และโมเดลทำได้กี่ข้อ ทำด้วย `../rehearsal.py build`

```
rehearsal/
├─ test_dataset/        ← 500 ภาพ ts_img_001.jpg … ts_img_500.jpg   (ชี้ให้สคริปต์วันแข่งอ่านโฟลเดอร์นี้)
├─ answer_key.csv       ← เฉลย 500 แถว เรียงตามชื่อภาพ
├─ report_per_class.csv ← ความแม่นรายคลาส (คำสั่ง eval)
├─ report.md            ← สรุปผลจาก eval ที่อ่านง่าย
└─ README.md            ← ไฟล์นี้
```

## 2) ใช้ทำอะไร

1. **ซ้อมขั้นตอนวันแข่งทั้งหมด** — วางโฟลเดอร์ → รันสคริปต์ → ได้คอลัมน์ class_id → ตรวจว่าตรงเฉลยไหม
2. **วัดความแม่น** ของโมเดล CNN2 / FOURTH บนภาพครบทุกคลาส ไม่ใช่คลาสเดียวแบบชุดจำลองของ TAR (คลาส ก คลาสเดียว)
3. **เทียบโมเดล** ด้วยชุดเดียวกัน เพื่อช่วยตัดสินใจว่าจะส่งตัวไหน (ดูข้อ 7 ว่าเทียบแบบไหนยุติธรรม)

## 3) อ่านให้ถูก: ภาพ "สะอาด" กับภาพที่โมเดลเคยเห็น

โมเดลแต่ละตัวฝึกด้วยภาพ 80% ของข้อมูล และกันอีก 20% ไว้ตรวจ (แบ่งด้วยโค้ดและ seed 42 ของ `TrainingCNN.py` แต่ละ repo — `rehearsal.py` สร้างการแบ่งนั้นกลับมาให้ตรงเป๊ะ ดูข้อ 8) ภาพที่ **ทั้ง CNN2 และ FOURTH ไม่เคยฝึก** เรียกว่า **"สะอาด"** ความแม่นที่วัดจากภาพสะอาดเท่านั้นที่บอกความสามารถกับภาพใหม่ได้

คลาสหายากมีภาพสะอาดไม่พอ (ฃ และ ฑ มีภาพในข้อมูลทั้งหมดแค่อย่างละ 1 ภาพ) เพื่อให้ **ครบ 72 คลาส** ผมจึงเติมด้วยภาพที่โมเดลอย่างน้อยหนึ่งตัวเคยเห็น และ **ติดป้ายไว้ทุกแถว** ในคอลัมน์ `trained_by`:

| ค่า `trained_by` | หมายถึง | จำนวนใน 500 ภาพ |
|---|---|---|
| `none` | ทั้งสองโมเดลไม่เคยฝึกด้วยภาพนี้ = **สะอาด** | 345 |
| `fourth` | เฉพาะ FOURTH เคยฝึก (CNN2 ไม่เคย) | 70 |
| `cnn2` | เฉพาะ CNN2 เคยฝึก (FOURTH ไม่เคย) | 58 |
| `both` | ทั้งสองเคยฝึก (คลาสหายากที่ภาพไม่พอ) | 27 |

- คลาสที่ได้ภาพน้อยกว่า 6 ภาพ (เพราะมีภาพในข้อมูลไม่พอ): ฃ (1), ฑ (1), ฬ (3), ๗ (4) และทั้งหมดเป็นภาพที่โมเดลเคยเห็น
- แต่ละคลาสได้ 6–8 ภาพ ยกเว้นคลาสข้างบน (500 ÷ 72 ≈ 6.9)
- **ตัวเลขความแม่นให้อ่านแยกแถว `none`** เสมอ แถวอื่นแม่นเกินจริงเพราะเคยเห็นตอนฝึก

## 4) ใช้ยังไง

`<REHEARSAL>` = โฟลเดอร์นี้ (พาธไหนก็ได้ ทั้ง absolute และ relative) · `<TOOLS>` = โฟลเดอร์ที่มี `rehearsal.py` (`test days/`) · `<TEST_DAY>` = โฟลเดอร์ที่มี `predict_test_embed.py` และ `model.pt` (เช่น `CNN2/test_day`) · พาธที่มีช่องว่างให้ใส่เครื่องหมายคำพูดครอบ

### วิธี A: ชี้พาธตรง ๆ (ไม่ต้องก๊อปภาพ) — แนะนำ
```
cd <TEST_DAY>
python predict_test_embed.py --model model.pt --test-dir "<REHEARSAL>/test_dataset" --group NPC --out predictions_NPC.csv
python "<TOOLS>/rehearsal.py" --key "<REHEARSAL>/answer_key.csv" score predictions_NPC.csv.values.txt
```
- `--test-dir` รับพาธอะไรก็ได้ ไม่จำเป็นต้องชื่อ `test_dataset` หรืออยู่ข้างสคริปต์
- `score` รับได้ทั้งไฟล์ `.values.txt` (class_id บรรทัดละค่า) และ `predictions_NPC.csv`; `--key` ชี้ไฟล์เฉลยที่ไหนก็ได้ (ต้องใส่ **ก่อน** คำว่า `score`)
- `--model` ชี้โมเดลตัวอื่นได้ เช่น `../../CNN_font_and_nofont/model.pt` หรือ `model_nofont.pt`
- `--out` กำหนดที่เขียนผลได้ (ค่าเริ่มต้นเขียนลงโฟลเดอร์ที่ยืนอยู่)

### วิธี B: รันผ่านสคริปต์วันแข่งตามขั้นตอนจริง (ซ้อมมือ)
1. ก๊อปโฟลเดอร์ `<REHEARSAL>/test_dataset` ไปวางใน `<TEST_DAY>/`
2. ดับเบิลคลิก `run_embed.bat` (หรือ `python predict_test_embed.py --model model.pt --test-dir test_dataset --group NPC`)
3. ตรวจคะแนน: `python "<TOOLS>/rehearsal.py" --key "<REHEARSAL>/answer_key.csv" score predictions_NPC.csv.values.txt`
4. **ลบโฟลเดอร์ `test_dataset` ที่ก๊อปมาก่อนวันจริง** เพื่อไม่ให้ชุดซ้อมปนกับชุดจริง

### วิธี C: ให้สคริปต์สร้างชุดซ้อมเอง (เปลี่ยนขนาด / ที่เก็บ / ตำแหน่งข้อมูลได้)
```
python rehearsal.py [ตัวเลือก] build
```

| ตัวเลือก (ใส่ **ก่อน** คำสั่ง) | ทำอะไร | ค่าเริ่มต้น |
|---|---|---|
| `--cnn2 <DIR>` | โฟลเดอร์ repo CNN2 (ต้องมี `dataset/round2` และ `model.pt`) | `<โฟลเดอร์แม่ของสคริปต์>/CNN2` |
| `--fourth <DIR>` | โฟลเดอร์ repo FOURTH (ต้องมี `dataset/round2`, `model.pt`, `model_nofont.pt`) | `<โฟลเดอร์แม่ของสคริปต์>/CNN_font_and_nofont` |
| `--out <DIR>` | ที่เก็บผลลัพธ์ (`test_dataset/`, `answer_key.csv`, รายงาน) | `<โฟลเดอร์ของสคริปต์>/rehearsal` |
| `--n <N>` | จำนวนภาพในชุดซ้อม | 500 |
| `--seed <S>` | เมล็ดสุ่มตอนเลือกภาพ (**ไม่กระทบว่าภาพไหนนับว่าสะอาด**) | 42 |
| `--key <CSV>` | ไฟล์เฉลยที่ใช้กับ `score` | `<out>/answer_key.csv` |
| `--model ชื่อ=พาธ` | เพิ่ม/แทนโมเดลใน `eval` (ใส่ซ้ำได้) | 3 ตัว: cnn2, fourth, fourth_nofont |
| `--predict-script <PY>` | ตำแหน่ง `predict_test_embed.py` | ข้างสคริปต์ |

ตัวอย่าง (เครื่องอื่น พาธอื่น ไม่ต้องแก้โค้ด):
```
python rehearsal.py --cnn2 /data/CNN2 --fourth /data/fourth --out /tmp/reh --n 300 --seed 7 build
python rehearsal.py --out /tmp/reh score /tmp/reh/pred.csv.values.txt
```
รันสร้างซ้ำด้วยค่าเดียวกัน ได้ชุดเดียวกันทุกแถว (ทดสอบแล้ว `answer_key.csv` เหมือนเดิม) `build` **ลบเฉพาะโฟลเดอร์ `test_dataset` ที่มันสร้างเอง** และ **ปฏิเสธ** ถ้าเจอไฟล์อื่นปนอยู่ ไม่ลบไฟล์อื่นในโฟลเดอร์ `--out`

### วัดรายคลาส / ตรวจความถูกต้อง
```
python rehearsal.py eval      # ความแม่นรายคลาสของ 3 โมเดลบนภาพสะอาดทั้งหมด (2,509 ภาพ) ใช้เวลา ~4 นาทีบน CPU
python rehearsal.py verify    # พิสูจน์ว่าการแบ่ง 20% ที่สร้างกลับมาตรงกับตอนฝึก (ช้า ~20 นาทีบน CPU)
```

## 7) ข้อจำกัด (สำคัญ)

- **ไม่ใช่ชุดจริง:** เป็นภาพจากชุดข้อมูลเดิมของรายวิชา ถ้าชุดจริงของอาจารย์มาจากลายมือคนละกลุ่ม ความแม่นจริงอาจต่ำกว่า 97–99% ที่เห็นนี้ (ตัวอย่างที่เคยวัด: ชุด font test ได้ 78–97% ตามโมเดล)
- **ไม่รู้สัดส่วนคลาสของชุดจริง:** ชุดซ้อมสมมติคลาสละ ~7 ภาพ ทำให้คลาสที่ภาพเยอะแต่พลาดง่าย (า, ๅ) มีน้ำหนักน้อยกว่าในข้อมูลจริง ตัวเลขข้อ 6 ตารางบน (500 ภาพ) จึงสูงกว่าตารางล่าง (2,509 ภาพ)
- **การเทียบโมเดลที่ยุติธรรมที่สุด** คือดูภาพสะอาดของ `eval` เพราะเป็นภาพที่ทั้งคู่ไม่เคยฝึก แต่ทั้งสองยังใช้ชุด 20% นี้เลือกโมเดล/หยุดฝึก (CNN2: EarlyStopping ตาม val_loss, FOURTH: เลือก checkpoint ด้วยคะแนนเฉลี่ย) จึงไม่ใช่ชุดทดสอบที่ "ไม่เคยแตะเลย" แต่ไม่ได้ถูกใช้ปรับน้ำหนักตรง ๆ
- ภาพทั้งหมด 500 ภาพเป็นภาพต้นฉบับ ไม่ได้ย่อ/ขยาย/แปลงเพิ่ม จึงไม่มีภาพขนาดสุดขั้ว (7×11, 180×177) เหมือนช่วงที่โจทย์บอก

## 8) การตรวจสอบว่าการแบ่ง 20% ถูกต้อง

`python rehearsal.py verify` สร้างการแบ่ง 20% ของแต่ละ repo กลับมาแล้วรันโมเดลบนภาพเหล่านั้น เพื่อดูว่าตรงกับตอนฝึกจริงหรือไม่ (log ดิบอยู่ใน `verify_log.txt`)

| ตรวจอะไร | ผลที่ได้ | สรุป |
|---|---|---|
| FOURTH: ขนาด val ที่สร้างกลับมา | 12,545 ภาพ | ตรงกับ log การฝึกของ FOURTH (12,545) |
| FOURTH `model.pt` บน val นั้น | ถูก 12,213 / 12,545 = 97.35% | **ตรงเป๊ะ** กับที่บันทึกไว้จากการรันก่อนหน้า (12,213) |
| FOURTH `model_nofont.pt` บน val นั้น | ถูก 12,243 / 12,545 = 97.59% | **ตรงเป๊ะ** กับที่บันทึกไว้ (12,243) |
| CNN2: ขนาด val ที่สร้างกลับมา | 12,542 ภาพ | ไม่มี log ให้เทียบ |
| CNN2 บน val นั้น | ถูก 12,157 / 12,542 = 96.93% | ไม่มีเลขอ้างอิงให้เทียบ |

**สรุป**
- **การแบ่งของ FOURTH พิสูจน์แล้วว่าถูกต้อง** (ตรงเป๊ะสองโมเดล ที่ระดับจำนวนภาพ) ตัวเลขของ FOURTH ในคู่มือนี้เชื่อถือได้
- **การแบ่งของ CNN2 ยังไม่ได้พิสูจน์แบบเป๊ะ** เพราะ CNN2 ไม่มี log การฝึกให้เทียบ ใช้โค้ดและ seed เดียวกับ `TrainingCNN.py` ของ CNN2 (`random_split` + `Generator().manual_seed(42)`) หลักฐานแวดล้อมที่สนับสนุน: โมเดลได้ผลบนภาพที่กันไว้ **ต่ำกว่า** ภาพฝึกเล็กน้อยในทิศทางเดียวกับ FOURTH ที่เป็นตัวควบคุม (สุ่ม 3,000 ภาพ: ภาพที่กันไว้ loss 0.1204 / ถูก 96.50% เทียบภาพฝึก loss 0.0972 / ถูก 97.43%; ตัวควบคุม FOURTH loss ต่างกัน +0.0159 เทียบ CNN2 +0.0232) แต่ส่วนต่างเล็กและอยู่ในระดับความคลาดเคลื่อนจากการสุ่มราว 1–2 เท่า จึง **สนับสนุนแต่ไม่ถือเป็นการพิสูจน์**
- **ถ้าการแบ่งของ CNN2 ผิด จะกระทบอะไร:** เฉพาะป้าย "สะอาด" (`trained_by = none`) อาจปนภาพที่ CNN2 เคยฝึก ทำให้ความแม่นของ CNN2 บนภาพสะอาดสูงเกินจริงเล็กน้อย ตัวเลขของ FOURTH ไม่กระทบ

**วิธียืนยัน CNN2 แบบเด็ดขาด (ให้ TAR รัน ใช้เวลาไม่ถึง 1 นาที ไม่ต้องมีภาพ)** ต้องใช้ Python + torch เวอร์ชันเดียวกับที่ใช้ฝึก:
```python
import torch
from torch.utils.data import random_split
_, v = random_split(range(62707), [50165, 12542], generator=torch.Generator().manual_seed(42))
print(v.indices[:10])
```
ผลที่ต้องได้ (ตรงกับที่เครื่องนี้สร้าง): `[25111, 47481, 8392, 26165, 23808, 52351, 8143, 34465, 6425, 43568]` ถ้าตรง = การแบ่งของ CNN2 ตรงกัน (ตัวเลขนี้ตรวจแล้วว่าให้ผลเหมือนกับวิธีที่ใช้ `ImageFolder` จริง) ถ้าไม่ตรง แปลว่า torch คนละเวอร์ชัน ให้แจ้งเพื่อสร้างป้ายใหม่
